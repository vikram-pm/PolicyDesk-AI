1Benchmark

Copy the capability, not the context

The brief was an MVP like Reapdat, an AI front desk for small businesses. I broke it into features and asked what each one means for a regulated life insurer.

Reference featureBuilt forInsurance adaptation in PolicyDesk
Web chat widgetAnswering and bookingAnswers from approved content only, source logged per reply
Browser voice callsAfter-hours callsTwo-sentence spoken replies, typed fallback, transcript to the portal
Email auto-replySupport inboxAuto-reply only when safe; otherwise a drafted reply goes to a specialist
Appointment bookingSalons, clinicsPolicy reviews with licensed financial professionals
"Needs you" queueUncertain casesBecame the core feature: bereavement, advice, fraud, surrender and policy-specific questions
One knowledge baseConsistencySingle source of truth that compliance can sign off

Key insight: an SMB front desk optimises bookings. An insurer optimises trust. So handoff rules moved from an edge case to the centre of the product.

2Product requirements

PRD: what, for whom, and how we know it works

Problem statement

Policyholders need fast, accurate answers to routine service questions at any hour, and sensitive requests must reach a qualified person with context, not a bot.

Users

  • Maria, policyholder: wants a plain answer after hours
  • Linda, beneficiary: needs warmth and a person
  • James, specialist: wants routine volume gone, full context on handoffs

Assumption-based personas, validated in pilot discovery.

#FeatureAcceptance criteria
F1Web chatKB answers with source; captures name, email, phone; “Talk to a person” escalates
F2Voice callSpeech in and out, ≤2 sentences, typed fallback, transcript saved
F3Email supportAuto-reply when answerable, else routed with draft; reply time logged
F4Review booking5 days × 5 slots, taken slots disabled, confirmation, contact created
F5Needs you queueDraft with AI, edit, send, save to KB; reply reaches the original channel
F6Knowledge baseAdd, edit, delete, file upload; applies to every channel next message
F7Assistant setupName, tone, model, language, handoff toggles, share link and QR
F8PortalDashboard KPIs, conversations, inbox, reviews, contacts (CSV)

Always to a person

Death claims, complaints, policy surrender, fraud, requests for a person, personal advice, policy-specific questions, anything outside the knowledge base.

Success metrics

Answer accuracy ≥ 90%, escalation recall 100%, escalation precision ≥ 85%, email reply < 60 s. Pilot: AI resolution ≥ 35%, CSAT ≥ 4.2.

Full PRD: goals, non-goals, Responsible AI, rollout and risks.

3Design

Design: calm, trustworthy, on brand

Version 1: Cognizant palette

First MVP in Cognizant midnight blue and cyan, built to prove the flows end to end. Single-column landing page with a floating widget.

Version 2: New York Life brand, reference layout

Restyled to a New York Life-style navy and blue, softened with pastel gradients from a chatbot UI reference: serif display headline, floating performance and upload cards, a three-column console (navigation, live chat, AI settings) and a mobile preview.

Colour tokens

NavyBlueSkyVioletRose

Approximations; swap in official brand values for a real engagement. No New York Life logos used.

Type

DM Serif Display for headlines, Plus Jakarta Sans for interface text. Both from Google Fonts.

Quality floor

Light and dark themes with a toggle, responsive to 390 px, visible keyboard focus, reduced-motion support.

UX decisions that came from the insurance context

Handoff before answer. Rules run first, so a bereavement message never gets a product answer.

Show the source. Each AI reply names the knowledge-base entry it used, which builds trust and gives compliance an audit trail.

Next steps under every escalation. Book a review, call or email buttons, so a handoff never ends in a dead end.

Drafts for specialists. The Needs you queue arrives with a reply drafted, and one click saves it back to the knowledge base.

Two engines, one interface

On claude.ai, Claude writes each answer from the knowledge base and returns JSON (reply, escalate, reason, source). Everywhere else, including GitHub Pages, a keyword-scoring rules engine answers from the same knowledge base. The demo never depends on an API key.

Deliberately simple stack

One HTML file, vanilla JavaScript, no build step and no backend. State lives in the browser so anyone can run the full demo, and it resets cleanly.

Prompt contract for the live engine

You are {name}, the 24/7 service assistant for New York Life policyholders.
Answer ONLY using the knowledge base below. Tone: {tone}. {creativity rule} {language}.
Rules: never give personalised financial, tax or legal advice; never ask for SSN,
bank details or policy number; if the topic is {handoff list}, a request for a person,
personal advice or policy-specific, set escalate=true and reply with empathy.
KNOWLEDGE BASE: [1..n] Q/A   CONVERSATION SO FAR: last 8 turns
Return ONLY JSON: {"reply","escalate","reason","source","offerBooking"}

Rules also run locally first, so if the model misses a sensitive case the local check still escalates it.

How I worked with AI: the 4D framework

Delegation

I owned scope, insurance rules and every product decision. Claude did research synthesis, code and drafting.

Description

Briefs named the client, constraints, brand and acceptance criteria; the in-product prompt is a strict JSON contract.

Discernment

I tested outputs instead of trusting them: the eval caught 2 unsafe answers, and screenshots caught a mobile overflow bug.

Diligence

Disclaimers, no client logos, placeholder data, and honest metrics: held-out score reported, not the tuned 100%.

Unsafe: advice

“Should I buy term or whole life?” got a product answer. Fix: advice rule routes to a licensed professional.

Unsafe: coverage guess

“Does my policy cover skydiving?” needs the contract. Fix: policy-specific rule requires verification.

False alarm

An annuity “surrender charge” question went to retention. Fix: narrowed to surrendering a policy.

The one held-out miss was an over-escalation, the safe direction to fail. Reproduce with node eval/run_eval.js holdout.json.

Learnings

Context changes the product

Same channels as an SMB tool, different centre of gravity: trust over bookings.

Fail safe by design

Over-escalating costs a minute. A wrong answer to a beneficiary costs trust.

Test what AI builds

AI wrote most of the code fast; the test set and screenshots are what made it trustworthy.
